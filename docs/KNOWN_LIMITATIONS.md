# 已知限制

发布说明只讲这一版改了什么。「这一版仍然做不到什么」记在这里，按主题归类，跨版本累积。

新增一条时写清楚**现象**和**为什么**，读者才能判断它会不会影响自己。某条不再成立时直接删掉，不要留「已修复」的注脚——历史在 git 里。

## Agent 功能

- **记忆建议只能在 Studio 里确认**。Studio 2.58 起，模型提议的记忆会先扣在电脑上，等用户接受、编辑或放弃；手机只显示工具的「已暂存」结果，设置里没有记忆页，所以不能确认或编辑这些建议。要处理请打开 Studio 的「设置 → 数据 → 记忆」。

## 通知

- **heads-up 弹窗宽度由系统决定**。任意长的问题无法在弹窗里完整显示，展开通知或点进会话才能看全文。
- **「会话完成」通知不强制横幅**。它进入通知栏；是否弹横幅由系统通知频道决定，不像 ask 那样强制 heads-up。
- **后台 watcher 需要 App 先知道这个回合**。局域网后台提醒要求 App 在退到后台前已经看到运行中/待处理回合。在电脑上新开始、手机完全不知情的回合，Android 12+ 不允许后台临时启动前台服务去补抓。

## 震动

- **打开「回答开始与结束」后，切换会话可能多震一次**。该开关默认关闭。打开后，若会话从缓存水合或历史合并中重建了行，新的行 id 会被当成「新回答开始」而震一下——用户并没有发出新问题。根因是 `useStreamHaptics` 只拿到行数组，缺少「这是真实流式开始」的信号；干净的解需要把水合/历史状态传进去，属于更大的重构。默认关闭把影响面压到主动开启的用户。

## 工作台

- **手机端没有「丢弃变更」和「推送」**。内核把 `POST /changes/discard`、`GET/POST /git/push` 和全部终端路由列在 host-only 表里（`internal/frontend/serve/host_routes.go`）——配对设备的凭据较弱，破坏性操作与外发操作只留给宿主窗口。这是内核侧的设计，App 无法也不应绕过。工作台里因此不渲染丢弃按钮，提交卡也只说「仅本地提交，不会推送」；丢弃与推送请回桌面端操作。`POST /changes/stage`、`POST /commit/propose`、`POST /commit` 都不在表里，手机可以暂存与提交。

## 连接

- **云端附件上传没有进度显示**。bulk 分块上传（`src/net/relayBulk.ts`）有断点续传和
  60 s 无进展看门狗，但进度没有跨过 fetch 拦截层传到输入框——拦截层只看见一个
  `POST */attachments` 请求，不知道调用方是谁。要做进度条需要先设计进度事件的关联
  方案（上传 id 穿过 fetch 接缝），属于独立改造，设计文档 CLOUD_MUX_PLAN.md 在 Reasonix 工作区根（本仓库之外）。
  现在的表现是大附件上传期间输入框无反馈，最长 60 s 后报错。

- **电脑内核重启后，手机可能要重新扫码配对**。内核的 `[serve] remember_paired_devices` 默认关闭，重启后设备登记表不回填，手机里的 `reasonix_device` 凭据随之失效；此时重试旧地址不会恢复，App 会在连接卡片上给出「重新扫码配对」按钮。想跨重启保留配对，在电脑的 `config.toml` 里设 `remember_paired_devices = true`——这是内核侧配置，App 无法代改。
- **回前台会重建一次事件流**，即使流是健康的。这是修复「后台断连后对话不再更新」的代价：僵尸连接的 `readyState` 仍是 `OPEN`，没有更低成本的判定手段。重建带 cursor，不丢不重（见 #95）。
- **`phase !== "connected"` 时回前台不自愈**。`reassess` 在链路状态不是 connected 时直接返回，属于既有行为，未纳入本次范围。

## 内容渲染

- **新消息带时间戳，历史消息没有**。wire 的事件不带每条消息的时间，只有实时到达的行
  能在本地打钟（`transcript.ts`）；历史回放的行无从知晓当初的时刻。要一致只能改内核
  的事件契约（给 message/turn 帧加时间），属于跨仓库改动。

- **超宽表格的固定列在窄屏下会被挤压**。长内容列没有换行上限时会把短列挤到只剩一个字宽；`table-wrap` 已支持横向滚动，但列宽分配仍由浏览器决定。
